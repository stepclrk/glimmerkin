# The Android app

Glimmerkin on Google Play is a Trusted Web Activity: a thin Android package, `io.flokr.glimmerkin`, that opens
`https://glimmerkin.flokr.io/play` in Chrome, full screen, with no address bar. It holds no copy of the game, so
every deploy of the site reaches the app by itself. Section 5 of `GLIMMERKIN_MASTER_SPEC.md` has the design.

## What is here

| Path | What it is |
| --- | --- |
| `app/`, `build.gradle`, `gradlew` | The Android project, generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) 1.27 and kept as generated, except where noted below |
| `twa-manifest.json` | The settings Bubblewrap generated the project from. A record, and what `bubblewrap update` reads if the project is ever regenerated |
| `icons.mjs` | Draws the launcher icons and splash image from `server/src/install.ts` before a build. The repository holds no image files, so the `.png` files are ignored by git |

Changed from what Bubblewrap generates: icons are drawn at build time rather than stored; the release signing key
and the version come from environment variables; `jcenter()` is replaced by `mavenCentral()`; and the
`package` attribute is gone from `AndroidManifest.xml`, because the Android build tools now take it from `namespace`.

The project uses Google's [android-browser-helper](https://github.com/GoogleChrome/android-browser-helper)
library (Apache 2.0), which is what opens the site in Chrome, and the Gradle wrapper (`gradle/wrapper/`), which
CI checks is Gradle's own.

## Building

Nobody needs Android tools on their own computer. GitHub Actions does both builds:

- **Every pull request** builds a debug app and an unsigned release bundle (the "Android app builds" job in
  CI), and checks the package name, the address it opens, the target API level (36, as Google Play requires
  from 31 August 2026) and that it asks for no permissions.
- **A release** is built by hand: Actions, "Android release", "Run workflow", with a version name such as
  `1.0.0`. It signs the bundle with the upload key and keeps `app-release.aab` as a download on the run's page
  for 14 days. The version code is the run number, so it goes up with every release, as Google Play requires.

To build on a computer with the Android SDK and Java 17:

```sh
(cd server && npm ci && npm run build)
node android/icons.mjs
cd android && ./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
```

## The upload key

Google Play signs the app people install with its own key (Play App Signing). You sign each upload with an
**upload key**, which proves the upload came from you. It is made once, and it is yours:

- It never goes in this repository (`.gitignore` refuses `*.p12`, `*.jks` and `*.keystore` here) and never on
  the game's server.
- It lives in two places: the repository's GitHub Actions secrets, which the release workflow reads, and your
  password manager, as the backup.
- If it is lost or leaks, Google Play support can reset it. That is why it is the upload key that sits in
  GitHub, not the key that signs the app on people's phones.

Make it on a Mac or Linux computer (on Windows, in Git Bash), in an empty folder:

```sh
openssl req -x509 -newkey rsa:4096 -sha256 -days 10000 -nodes -subj "/CN=Glimmerkin upload key" \
  -keyout key.pem -out cert.pem
openssl pkcs12 -export -name upload -inkey key.pem -in cert.pem -out glimmerkin-upload.p12
# It asks for a password twice. Make a long one and keep it in your password manager.
base64 < glimmerkin-upload.p12 | tr -d '\n' > glimmerkin-upload.base64.txt
rm key.pem cert.pem
```

Then, in the repository on GitHub, Settings, Secrets and variables, Actions, add two repository secrets:

| Name | Value |
| --- | --- |
| `UPLOAD_KEYSTORE_BASE64` | The contents of `glimmerkin-upload.base64.txt` |
| `UPLOAD_KEYSTORE_PASSWORD` | The password |

Put `glimmerkin-upload.p12` and its password in your password manager, then delete the two files from the folder.

## Making the site vouch for the app

Chrome hides its address bar only when `https://glimmerkin.flokr.io/.well-known/assetlinks.json` names the
app and the fingerprint of the key that signed it. Without that the app still works, but shows a thin
browser bar at the top. Two fingerprints go in, separated by a comma:

1. **The app signing key**: Play Console, the app, Test and release, Setup, App signing (some versions of the
   console call it App integrity), "SHA-256 certificate fingerprint" under "App signing key certificate". This
   is the key on every phone that installs from Google Play. It exists only once the first bundle is uploaded.
2. **The upload key**: printed on the summary page of every "Android release" run. Needed only for a copy
   installed straight from the `.aab` rather than from Google Play.

On the server:

```sh
cd /opt/stacks/glimmerkin
nano .env      # ANDROID_CERT_FINGERPRINTS=<app signing key>,<upload key>
docker compose up -d
curl https://glimmerkin.flokr.io/.well-known/assetlinks.json
```

The last line shows the two fingerprints. A mistyped one is left out, and the server logs which.
