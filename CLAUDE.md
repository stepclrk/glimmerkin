# Glimmerkin: working rules

Glimmerkin is a creature-care and quest game. `GLIMMERKIN_MASTER_SPEC.md` is the sole canonical spec. Read it
before changing anything.

## Rules

1. **Never commit to `main`.** Branch, push, open a pull request. The owner merges.
2. **A design change updates `GLIMMERKIN_MASTER_SPEC.md` in the same pull request.** Decisions made in chat
   or on a board are folded into the spec the same day.
3. **The game ships as it is.** Do not redesign, reskin or rebalance it as a side effect of other work. A
   change to the game is its own pull request with its own reason.
4. **Nobody meets a sign-in screen before they can play.** `/play` never requires an account.
5. **The Docker stack publishes port 7777.** Do not change it; the Cloudflare Tunnel points at it.
6. **No AI in the runtime path.** Worlds and creatures are generated by code.
7. **Third-party code is fine, and is always declared.** The pull request says what was added and why.
8. **Store nothing personal.** A username, a password hash and one save per player. No email, no real names.

## Stack

| Part | What |
| --- | --- |
| Game client | Plain JavaScript on a canvas, in `src/`, concatenated into one page by `build.sh`. No libraries |
| Server | Node 22, TypeScript and Fastify in `server/`, with Postgres 16, in a Docker Compose stack |
| Backups | `backup/backup.sh` in its own container: nightly `pg_dump`, encrypted with `openssl` |
| Pages around the game | Plain HTML, CSS and JavaScript in `server/pages/`. No libraries, nothing inline |
| Front door | A Cloudflare Tunnel, set up by the owner, carrying `glimmerkin.flokr.io` to port 7777 |

## Commands

```sh
sh build.sh                 # build the game into dist/index.html
node test/syntax.js         # the built script parses
node test/gen.test.js       # 6,000 generated worlds, none unfinishable
node test/bonus.test.js     # secret doors and every bonus world's generator are fair
node test/grounds.test.js   # 4,000 gardens, every one walkable all over, every bed and hidden place in reach
python3 test/smoke.py       # browser: full quests in every world type
python3 test/features.py    # browser: tools, charms, toys, trader, journal, boss worlds
python3 test/depth.py       # browser: wishes, world rules, littles together, Mythic forms, the journey, the nest
python3 test/bonus.py       # browser: the secret door and each bonus world behind it
python3 test/rhythm.py      # browser: the gentle start, what's new, today's world, seasons, December's gifts, friends' eggs, grown-up littles
python3 test/play.py        # browser: nest play with the Glimmerkin and the littles
python3 test/garden.py      # browser: the garden: walking, planting, tending, picking, hidden places, the map
python3 test/cloud.py       # browser: account-save behaviour against a stand-in for the Claude store
( cd server && npm ci && npm run lint && npm test )    # server: type-check and tests (DATABASE_URL: see README)
sh setup.sh && docker compose up -d --build && python3 test/hosted.py  # browser: the running stack on port 7777
```

The browser tests need `pip install playwright` and `playwright install chromium`. Set `CHROME_PATH` to use
an existing Chrome, and `SHOTS_DIR` to choose where screenshots go. Each prints `ALL CHECKS PASSED` or names
what failed, and exits non-zero on failure. CI runs all of them on every pull request, and builds the image.

## Code conventions

- **Game code** is one shared script scope across the files in `src/`, in the order `build.sh` lists them.
  `src/core.js` has no DOM access and must keep running in Node, because the generator test loads it.
- **Every generated world must be finishable.** Any change to `genWorld` or its inputs keeps
  `test/gen.test.js` at zero failures.
- **Bonus worlds** live behind a secret door. Each is one file that adds itself to `BONUS` (see `src/bonus.js`),
  with its generator in `src/core.js`. A bonus world can never be lost, and its generator is checked in
  `test/bonus.test.js` the way worlds are in `test/gen.test.js`.
- **The garden** (`src/grounds.js`) is built by `genGrounds` in `src/core.js` from the creature's seed, and the save
  names a bed and a hidden place by its number. A change to `genGrounds` keeps every seed's numbered beds and
  hidden places where they are, and keeps `test/grounds.test.js` at zero failures.
- **The save document** (`S` in `src/game.js`) carries `v: 1`. New fields get a default in `afterLoad` in
  `src/boot.js` so older saves still load. Never rename or remove a field without a migration.
- **Server code** is strict TypeScript, ES modules. `buildApp` in `server/src/app.ts` builds the server without
  listening, so tests drive it with `app.inject`. Every answer carries the security headers set there.
- **Database changes** are new entries in `MIGRATIONS` in `server/src/db.ts`. Never edit one that has shipped.
- **Every refusal** from the API is `{ error, message }`: a code for programs and a sentence for people.
- **Secrets** live in `.env` on the server, written by `setup.sh`. A new secret is added to `setup.sh` and
  `.env.example` together, so that an existing install picks it up on its next update.
- **Storage** goes through `loadLocal`, `saveLocal`, `save`, `initCloud` and `pushCloud` only. The account copy sits
  behind a store with `get` and `set`: `claudeStore` inside Claude, `serverStore` on the hosted site. The game
  must keep working in both, and from a `file://` page with neither.
- **Drawing** in the game is procedural. No image or sound files. The landing page's two screenshots in
  `server/pages/assets/` are the only images in the repository.
- **Words on screen**: UK English, sentence case, plain and specific. Errors say what happened and what to do.
- **Pages around the game** use the Flokr Design System. The game keeps its own look.
